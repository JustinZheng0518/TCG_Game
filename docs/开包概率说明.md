# 开包概率与动画设计

本说明适用于常规补充包，目标是每包保 RR、不同稀有度不同概率、最高档平均千包一遇。特色包、预组、礼盒及活动卡使用[独立渠道规则](卡店经营与数据来源.md)，不套用五张补充包逻辑。下面的游戏概率不代表实体商品的官方封入率。已有收藏和备份格式保持兼容。

## 调研依据（2026-10-17）

查阅了宝可梦简体中文官网的具体商品说明：

- [极巨争锋系列商品说明，2023-04-30](https://www.pokemon.cn/tcg/product/16268.html)：明确写有 5 张装包含 1 张闪卡、25 张装包含 5 张闪卡。附赠补充包从 40 种卡中抽取，其中 15 种是出现概率较低的闪卡。**闪卡保证不能等同于 RR 保证**，也不能由此推算 SR、UR 的精确概率。
- [嗨皮组合：训练家的宝可梦，2026-09-21](https://www.pokemon.cn/tcg/product/23939.html)：明确公开闪卡卡组 1.6%、改造包卡比兽 ex 3.1%、奖赏包基本能量闪卡 87.5% / 宝可梦 ex 闪卡 12.5%，以及嗨皮包平卡 88.45% / 精灵球纹样 10.5% / 大师球纹样 1.05%。这些比例**仅适用于该商品的对应封入位置**，不能跨商品套用。

调研结论：各商品的张数、保底位置、加工版本和封入规则不同。采用“固定基础位置 + 独立保底位置 + 稀有机会位置”的模型方便明确展示概率，也方便后续为球星卡扩展球员、平行卡、签字卡等卡池。本次没有取得可核验的跨系列大样本开包统计；外部 TCGplayer 统计页在当前云环境被网络策略阻断，因此不引用其数字，不将自定概率写成统计结论。

## 每包 5 张

| 位置 | 游戏规则 |
| --- | --- |
| 第 1–3 张 | 基础卡池，档内卡面等概率；包含 C、U、R、无标记等，以及它们的加工版本 |
| 第 4 张 | 从本套 RR 卡面中等概率抽 1 张，独立保底 |
| 第 5 张 | 一次互斥的机会卡抽取，按下表选档，再在档内等概率选卡面 |

| 机会卡档位 | 基准每包概率 |
| --- | --- |
| RRR（同时存在 RR 时） | 15% |
| AR / CHR / S | 12% |
| SR / CSR | 6% |
| SSR / HR | 2% |
| SAR | 1% |
| UR | 0.3% |
| FUR | 0.1% |

**实际概率按当前 set 调整：最高的现存高稀有档固定为 0.1%。** 例如包含 SR、SAR、UR 而没有 FUR 的套装，机会位为 SR 6%、SAR 1%、UR 0.1%，其余 92.9% 回到基础卡池。若同时含有 RRR，另占 15%。如果只含 SR 和普通卡，SR 就是最高档，设为 0.1%。页面“开包概率与规则”会显示本套实际使用的概率。

缺少的档位不参与抽取，其概率回到基础卡池，不归一化提高其他高稀有档。高稀有卡仅在机会位置出现，因此 0.1% 是**每包**概率，不是每个卡位的概率。RR 保底不会被 SR / SAR / UR 等替换。

没有 RR、但有 RRR 时保 1 张 RRR；两者均没有时保底位置回到基础卡池，页面明确标注。没有基础卡、只有 RR / RRR 时，以 RR 或 RRR 作为基础卡池。只有高稀有卡的赠卡等商品采用整套等概率抽取，明确标注不适用千包稀有档。每个 set 中的全部卡面保持可获得。

卡面的 C★、C★★、U★ 等后缀是加工版本，不自动当作 SR 或 SAR。无字母稀有度的符号卡、无标记卡按基础卡池处理，不凭工艺符号虚构跨商品稀有度。这个规则按已有源数据执行，未来可以为特定商品配置独立工艺概率。

## “约一千包”是什么意思

最高档出现概率为 0.001，其首次出现的期望等待包数为 1 / 0.001 = 1,000。每包独立，没有累计保底；打开 1,000 包至少出现一次的概率约为 63.2%，并非必出。

最高档有 N 张卡面时，某一指定卡面的单包概率为 0.001 / N，期望等待为 N × 1,000 包。例如 30thC 有 2 张 FUR，任意 FUR 平均约 1,000 包，指定超梦 ex FUR 平均约 2,000 包。同一卡号的不同加工卡面在现有收藏中仍分别计数。

## 动画与收藏

采用拆包、展示卡背、点击逐张翻牌、稀有卡光效的简洁流程。卡包包装和卡背用 CSS 绘制。十包连开逐包呈现，可随时跳过查看全部 50 张；翻牌支持鼠标、触屏及键盘，减少动态效果偏好下直接切换。

抽取和保存先于动画完成。跳过、关闭、按 Esc 或刷新不会丢失已保存的卡，也不会再次抽取。存储失败时不开始动画、保留原收藏。

逻辑位于 `web/game-core.js`，动画位于 `web/pack-opening.js`。独立的 `packModel` / `createDrawer` 与展示层可作为后续球星卡抽包的基础。

## 验证

执行 `node --test tests/game-core.test.cjs`：检查独立 RR 保底、最高档 0.1%、缺失档位处理、全部 236 套卡表的可达性、百万包模拟、收藏和存档兼容性。模拟使用固定种子便于复现，各档结果检查是否处于理论值的 6 个标准差以内。
