# 简体中文宝可梦卡面库

本阶段收集真实简体中文卡面，按照发行商品/set 分套，作为后续网页抽卡游戏的素材基础。页面先提供资源浏览、筛选和放大查看，不包含抽卡概率或存档玩法。

## 来源与范围

主来源为 [duanxr/PTCG-CHS-Datasets](https://github.com/duanxr/PTCG-CHS-Datasets)，固定提交 `c3b6ac6ef803aad9d60e44d058359addf3a20883`。原始说明随整理过程保存在 `docs/sources/PTCG-CHS-Datasets-README.md`。

此快照含 **236 个独立商品代码、23,250 条卡面收录记录、20,713 个不同的上游卡片 ID**，包括主补充包、强化包、起始卡组、嗨皮组合、改造包、奖赏包、特典与活动商品。上游商品日期从 2022-10-27 至 2026-10-16，日期不做推测或补造。

`set` 在这里指上游独立商品代码；既保留主扩展包，也保留其独立起始卡组、奖赏包和活动产品。不会把所有特典卡压成同一个 `PROMO` 目录。每张卡的 `number` 保留完整分子/分母，同一卡号的不同闪卡使用独立 ID 与独立图片，不能只按卡号去重。

简中为独立发行卡池，历史英文、日本和繁体中文的 set 不能通过翻译标题变成简中版。之前的英文、多语言目录作为调研资料保留，不进入本图库。TCGdex 简中入口若干 `SV7`—`SV10` 条目出现繁体标题及不同于简中商品代码的编号，本次不采用其卡面。

另核对了 `zsjy947/PTCG-card-data` 的 2026-10-16 卡表快照：136 条索引中的四条空特典目录复用了 `PROMO` ID，因此不能把它们覆盖成一个空文件后当作完整历史卡池。本次采用有真实图片与独立商品代码的主来源。

这些数量证明对固定来源的覆盖，不保证历史上所有活动发放、特殊印刷、签名改造、错误印刷和后续新发售产品均已收录。当前实际缺图与逐套结果以 `coverage.json`、`missing-images.json` 为准。

## 目录结构

```text
data/pokemon/zh-CN/
  index.json                   # 236 套入口、每套卡面数和不同卡号数
  source-dictionaries.json     # 上游稀有度等词表
  image-manifest.json          # 实际图片 SHA-256、Git blob、尺寸、缩略图大小
  coverage.json                # 按 set 统计本地原图与缩略图是否齐备
  missing-images.json          # 尚缺卡面，齐备时为空数组
  sets/<set-code>/
    set.json                   # 名称、发行日期、来源商品 ID、计数
    cards.json                 # 该套全部卡面与变体
data/images/pokemon/zh-CN/<set-code>/
  <source-image-id>.png        # 保留上游原图
  <source-image-id>.webp       # 本地生成的网页缩略图，保留透明通道
```

卡片 ID 为 `<set-code>:<source-card-id>`，同一卡片跨商品再收录时仍可追溯并按商品浏览。源图片文件名不是印刷卡号，印刷卡号应读取 `number` 字段。

原图使用来源原生尺寸，已抽样观察到 300×419。不放大、重新翻译或通过生成图来伪装更高清的实物卡面。WebP 用于缩小网页传输体积，原始 PNG 保留用于查看与后续处理。

## 重复执行与完整性

安装方式见 README。可重复执行：

```bash
cd /workspace/TCG_Game
/workspace/card-assets-venv/bin/python tools/pokemon_cn.py prepare --workers 4
/workspace/card-assets-venv/bin/python tools/pokemon_cn.py report
```

`catalog` 仅重建逐套卡表；`prepare` 获取固定提交的归档并整理实际图片；`report` 根据归档凭据与本地文件生成数量和缺图报告。

- 元数据按固定 SHA-256 与 Git blob 校验。
- ZIP 读取时验证每个文件 CRC；逐张原图经 Pillow 验证并实际解码。
- 根据所有上游图片重算 Git blob 与目录树，必须与快照的 `img` Git tree `56a44f7831419a29711ce4399bffd8601986374c` 一致，才写入完整归档证明。
- 大归档下载中断时，会复用已接收且 CRC 正确的完整条目，再根据固定 Git 目录清单补齐缺失文件；每个补下载文件均核对预期 Git blob 和大小，不改变预期校验值。
- 保留原图 SHA-256、Git blob、尺寸和字节数。已有原图内容相同时复用，不同时停止，不覆盖用户文件。
- 本机有 4 核 CPU 配额，使用 4 个处理线程，最多暂存 12 个任务。源快照位于 `/workspace/card-source-cache/`，不创建额外项目检出或 Git worktree。

原图和快照体积较大，图片路径被 Git 忽略，但实际文件在当前仓库工作目录中。元数据、整理脚本与网页可正常版本管理。来源说明随项目保留，未向远程仓库推送图片。

## 浏览

在项目根目录启动 README 中的 HTTP 服务。页面通过相对路径读取本地 JSON 和图片，没有外部 API、CDN 或字体运行依赖。每套卡牌分批显示，图片惰性加载；手机显示两列卡牌，set 列表横向滚动；电脑显示侧栏与多列卡牌。

页面使用 DOM 文本节点展示来源名称，不把数据拼入 HTML。切换 set 时丢弃过期请求，避免快速切换后卡表错套。缺图显示缺图状态，不以其他语言卡面替代。

- 236 套均与固定来源卡表一致；23,250 张原图已实际解码并核对 Git blob，全部生成 WebP，缺图清单为空。
- 完整源图片目录树指纹一致；另有 209 个非卡面源文件也参与了目录完整性核对。
- 原图合计 5,860,794,039 字节，WebP 合计 834,098,306 字节，缩小约 85.8%。主要尺寸为 300×419（21,164 张）与 300×417（2,029 张）；其余尺寸保留来源原状，包含 9 张 868×1212 图片。
- 对照查看太阳&月亮喷火龙GX、剑&盾拉普拉斯V、朱&紫土台龟ex和30周年呆火鳄ex，均为真实简体中文卡面。
- 用 Chromium 实测桌面与 390px 手机布局：本地 WebP 与 PNG 原图正常加载、放大弹窗正常、收集啦151分弹切换正常；实图检查中没有卡图请求失败或页面脚本错误。
- set 搜索、卡名搜索、稀有度筛选、分页与手机两列布局通过检查；同名同号的四种火球鼠变体均保留。
- 中断 ZIP 的 CRC 损坏会被拒绝，未完成的最后条目可补下载；重复图片处理复用有效缩略图，修改过的已有原图不会被覆盖。
