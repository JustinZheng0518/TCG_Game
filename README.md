# 小小卡店：宝可梦与篮球收藏

电脑、手机都能玩的简体中文卡店经营小游戏。初始资金 ¥3,000，经营未拆封商品和单卡，收集喜欢的卡面。


新增 **篮球柜台、两类卡共用评级、卡展买卖交换**。篮球接入 150 个可玩系列、53,711 条卡面资料，另有 3,834 个历史系列索引；25,523 张已校验本地图片随仓库提供，其中 24,578 张覆盖当前收录的全部非普卡；篮球完整展示本地卡图，缺图时显示插画，限编号码在图外显示，不加遮挡画面的上下框。两类卡在获得时分别生成居中、四角、边缘、表面四项品相，送评依原有品相评分，不再随机重抽。限编卡逐张保存编号（如 45/50），贯通收藏、送评和卡展交易；概率预览使用 —/50。保留原始扫描素材与来源资料，5 张数字体验包及报价为游戏模拟。PSA / BGS / CGC / SGC 送评需付费等待，可取回独立评级卡。卡展支持散卡与评级卡买入、售出及补退差价交换。详见 [素材范围、玩法和现实差异调研](docs/篮球球星卡与评级卡展.md)。


**图片选系列与概率公示**：386 个系列都有本地封面，电脑大图网格、手机双列。开包区直接显示关键比例，点击“查看全部概率”可查卡位、卡种、每张卡的单份 / 十份获得概率，活动、预组和自选兑换也分别说明；评级中心同步公开本卡对应机构的分数与标签概率。详见 [封面来源与计算口径](docs/系列封面与概率公示.md)。

新版默认第一人称走进原创 3D 小店：WASD 平滑行走，拖动环顾，E 与眼前物品互动；电脑可点击“鼠标控制”锁定鼠标环顾，Esc 松开。手机使用左侧模拟摇杆行走，同时用右手滑动转向，操作菜单可切回方向键并调整转向速度。支持一键回到门口、切换俯瞰、大画面游玩，以及补货、柜台、卡册、活动快捷按钮。大画面中仍可开门、收银和打烊。顾客仍会进店挑货、排队付款；无法使用 WebGL 时自动使用 2.5D 场景。界面采用奶油、粉色与薄荷色，主要文字 16px 起，店里有兔子摆件、彩旗、吊灯、木纹地板和简中卡面海报，视角按屏幕比例调整，保持稳定视线。手机使用底部四区导航，经营明细在小窗口中打开。

- **进货与经营**：供货商进货、保留卡包出售或拆封收藏、买入 / 回收 / 寄售单卡，结算营业日、支付运营费用、提升口碑并扩建柜台。
- **独立获得渠道**：236 套分为常规补充包、特色包、预组、礼盒、赛事活动、任务、特典兑换与组合附属包。活动卡不再一律按五张 RR 包发放。
- **活动和任务**：打理店铺、经营目标、活动券、每日通讯码；官方活动特别包第五弹按 89% / 10% / 1% 工艺配比抽一张。
- **新闻与行情**：官方售价和新闻联网快照、带来源与时间的参考价、明确标注的模拟新闻影响；卡牌详情支持联网查价并手动核对版本，失败回退到模拟估值。
- **收藏和存档**：23,250 条真实简中卡面，按 set 浏览；现金、库存、寄售、报价和收藏一起保存。兼容旧版收藏，支持完整经营备份。

先在卡店打理店铺，或到“任务”窗口使用游戏码 `START-STORE`。进入“采购开包”选系列，可以一键买入并拆封；已有库存会优先使用，只为不足部分付钱。想留货出售则展开“补货到货架”。

“收藏卡册”默认汇总所有系列的已拥有卡牌，按稀有度优先展示，可搜索卡名、卡号及系列代码，再按需筛选系列或稀有度。“卖重复卡”对当前系列筛选范围内的收藏生效，全部系列时一起处理，每款留一张；可直接卖卡、上架寄售，也保留完整卡表 / 单卡买入入口。收藏只读取拥有卡牌所属系列的资料，读取失败会提示重试，不影响存档。“活动广场”分别进入活动、任务、礼盒和特典渠道。收银柜台中可管理货架和寄售；新闻、任务、账本、升级和存档都可通过场景入口或右上角设置按钮访问。点“开门营业”后，顾客会走到货架和寄售柜挑选，再到收银台等待付款。点“收银”逐位收款，也可勾选“自动收银”。打烊会完成剩余订单，显示当天账单并进入下一天；不再通过结算按钮凭空卖货。离开店面或切到后台会暂停营业，刷新可恢复未付款订单。

拆包时按住银色封口向右拖，短拖回弹，拉到底松手才撕开；配有可关闭的撕拉音效，也支持回车和跳过动画，已保存卡牌不会丢失。

所有资金及交易均为游戏模拟。42 套常规包以美版朱紫时期 US$4.49 历史建议价为统一游戏参考，按固定 $1 = ¥7 换算后叠加游戏行情，不声称是当前实价或每套简中商品的美国版本。保留 4 款简中商品的官方售价资料，其余商品和未查询单卡使用明确标注的模拟估值；没有默认全量实时简中成交价。外部单卡接口在本次云网络中受限，浏览器可尝试直连，详见 [卡店玩法、调研与行情接入](docs/卡店经营与数据来源.md)。

普通补充包继续使用独立 RR 保底、最高稀有档每包 0.1% 的游戏规则，参见 [概率依据](docs/开包概率说明.md)。特色渠道不使用这套普通包规则。

卡库仍为 **236 个商品/set、23,250 条卡面记录**，包括同一卡号的不同加工版本。完整整理与来源说明见 [简中卡面库](docs/简中卡面库.md)。图片默认从固定提交的 GitHub 图源读取，本地下载后优先使用缓存。

## 从 GitHub 运行

GitHub Pages 地址：<https://justinzheng0518.github.io/TCG_Game/>。网站需要保留路径末尾的 `/TCG_Game/`；首次启用或推送后，请以仓库 Actions 中的部署结果确认发布是否完成。

本仓库包含游戏代码、完整卡表、图片地址和数据工具。联网游玩不需要先下载几 GB 图片，也不需要 API 密钥或额外构建；Three.js 随站点提供。

```bash
git clone https://github.com/JustinZheng0518/TCG_Game.git
cd TCG_Game
python3 -m http.server 8765 --bind 0.0.0.0
```

打开服务根页面即可游玩。使用 HTTP 服务打开，直接双击本地 HTML 会限制 JSON 读取。

也可在 GitHub 仓库 **Settings → Pages → Deploy from a branch** 中选择 **main / (root)** 并保存，作为静态网站发布。本仓库带有 `.nojekyll`，无需构建。首次开启后若没有构建记录，可在来源设置正确后向 main 推送一次提交来触发发布。推送代码与部署完成是两件事；发布结果以 Actions / Pages 状态为准。

经营数据保存在当前浏览器，不会自动在电脑和手机之间同步；可通过“导出经营存档 / 恢复经营存档”转移。版本 2 备份经确认后整体恢复；旧版收藏仅合并卡牌，不重置资金。

## 检查游戏逻辑

```bash
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

`python3 tests/browser_basketball_assets.py` 在屏蔽 TCDB 外链的情况下验证电脑 / 手机稀有档图片、展开、详情与覆盖说明。

`python3 tests/browser_odds.py` 检查电脑 / 手机全系列图片选择与各渠道概率公示。

`python3 tests/browser_collectibles.py` 覆盖电脑、手机篮球开包、混合收藏、两类卡评级、刷新存档、保存失败回滚和卡展购买 / 交换 / 卖出。

已安装 Playwright 与 Chromium 的开发环境中，启动静态服务后可运行 `python3 tests/browser_shop.py`。该可选检查覆盖电脑与手机的第一人称移动、碰撞、触摸按键释放、跨系列收藏、筛选与交易，以及资料加载失败后的重试。`python3 tests/browser_controls.py` 另外检查鼠标锁定 / Esc、双指同时移动和转向、摇杆取消 / 弹窗停步、大画面营业及退出；这些测试工具不属于站点运行依赖。

## 可选：下载全部图片到本地

需要 Python 3 与 Pillow；原图与源快照需要数 GB 本地空间。

```bash
cd /workspace/TCG_Game
python3 -m venv --system-site-packages /workspace/card-assets-venv
PIP_CACHE_DIR=/workspace/card-source-cache/pip /workspace/card-assets-venv/bin/python -m pip install --disable-pip-version-check -r requirements-assets.txt
/workspace/card-assets-venv/bin/python tools/pokemon_cn.py prepare --workers 4
```

只重建元数据用 `catalog`，检查已归档数量用 `report`。重复整理会校验并复用已有原图和缩略图；遇到不同内容的已有原图会停止，保留用户文件。

来源为 [duanxr/PTCG-CHS-Datasets](https://github.com/duanxr/PTCG-CHS-Datasets)，图片链接固定于提交 `c3b6ac6ef803aad9d60e44d058359addf3a20883`。原图使用来源原生尺寸。本仓库不捆绑原始图片；可选的本地图片缓存被 Git 忽略。

`coverage.json` 与 `image-manifest.json` 保存的是资源整理机器上完成的全量校验证据，不表示新克隆的仓库已经包含原图文件；网页会自动使用 GitHub 图源。

## 场景与界面资源

`web/shop-world.js` 使用原创程序化模型构建立体小店，`web/shop-business.js` 驱动顾客走动、排队和收银，`web/shop-motion.js` 提供与帧率无关的行走、刹停与分步碰撞，`web/live-shop.css` 提供场景与撕包样式，`web/cozy-shop.css` 提供大字号及可爱风格界面，`web/shop-experience.css` 提供摇杆、大画面和操作层。Three.js r160 位于 `web/vendor/`，附 MIT 许可证；不使用参考游戏的模型或贴图。旧版插画 `web/assets/card-shop-scene.png` 保留在资源目录，主页已使用实时 3D。真实卡面继续使用卡库来源。经营存档保持版本 2，新增营业记录可自动迁移。一键补货拆包和每笔收银各采用一次存档写入，失败不会扣款或消耗库存。
